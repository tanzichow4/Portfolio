## 1. Goal and scope

**Goal.** Add the fixed 36px menubar with four keyboard-operable menus (tanzi.os, Windows, View, Help), the GitHub/LinkedIn/Email links, a theme toggle and an en-US "Sat 3:42 PM" clock. The menus open, restore and arrange windows and change theme, wallpaper and wobble. These three settings persist in `localStorage`, survive Restart and Tidy, and go through the single action path that T07's `TerminalEffect`s will also use.

**Already done, not redone:** the reducer actions `open`, `close`, `minimize`, `restore`, `minimizeAll`, `showAll`, `tidy` and `restart`, plus `TerminalEffect`, `prefersReducedMotion`, the inline theme script, the wallpaper tokens and the focus ring.

**Out of scope** (carried over): the boot screen and boot progress (T08), so Restart resets straight away. Also out: resetting window-internal state on Restart (T08), running `help` in the terminal (T07), the Terminal UI (T07), the Dock (T06), window contents (T07), the real résumé and links (T10, so a missing `/resume.pdf` is fine), mobile below 760px (T11), persisting window layout, tooltips beyond accessible names (T09), menu animations, and any change to `index.html`.

## 2. Acceptance criteria

AC1-AC41 are copied from `00-requirements.md` with the same numbers and meaning. The full text is there and is binding. Short form:

- **AC1.** The menubar is fixed to the top, full width, 36px tall, with `0 12px` padding and 13px text. Background is 72% bg via color-mix, with blur(10px) and a `0 1px 0` divider shadow. z-index is 1000, above all windows.
- **AC2.** A labelled landmark (`<header aria-label>`) wraps a labelled `role="menubar"`. Its triggers, in order: tanzi.os (600 weight, accent, decorative `CircleHalf`), then Windows, View and Help (400, neutral-300). Each trigger has 5px 10px padding and radius 6px. Background is text 8% on hover and text 10% while its menu is open.
- **AC3.** On the right, in order: three `LINKS` links (30x28, 16px icon, neutral-400 that turns to text color on hover, name = label), the theme toggle (moon in dark, sun in light, named "Switch to light/dark mode"), then the clock.
- **AC4.** GitHub and LinkedIn use `target="_blank" rel="noopener noreferrer"`. The Email link is a plain `mailto:` with no target.
- **AC5.** All menubar copy and accessible names come from `src/data.ts`. No email address or URL appears outside `data.ts`.
- **AC6.** Clicking a trigger toggles its menu. At most one menu is open.
- **AC7.** While a menu is open, hovering another trigger switches to it. Hovering does nothing when no menu is open.
- **AC8.** The menu closes on a pointer-down outside the menubar and dropdown (the desktop or a window, which still raises), on Escape, and when an item is chosen.
- **AC9.** Dropdown: top 34px, left-aligned to its trigger, min-width 240, padding 6, radius 14, surface background, shadow-lg. Items: 7px 10px padding, radius 6, 13px text. A 14px check column always reserves its space. The hint is 11px neutral-500. Hover is accent 16% and pressed is accent 26%. Dividers are 1px with a 5px 8px margin.
- **AC10.** Triggers are `menuitem` with `aria-haspopup="menu"` and `aria-expanded`. Each dropdown is `role="menu"`, labelled by its trigger.
- **AC11.** Item roles: `menuitem` for actions, `menuitemcheckbox` for the five window items and Wobbly, `menuitemradio` for the two radio groups (theme, wallpaper). Checkable items have `aria-checked`. Dividers are `separator`. Check icons are `aria-hidden`.
- **AC12.** Roving tabindex gives the menubar one tab stop, reached before any window control. ArrowLeft/Right wrap between triggers. Home/End go to the first/last trigger.
- **AC13.** On a trigger, Enter, Space or ArrowDown opens the menu and focuses the first item. ArrowUp opens it and focuses the last item.
- **AC14.** In a menu, ArrowUp/Down wrap and skip separators. Home/End go to the first/last item. Enter or Space activates. ArrowLeft/Right open the previous/next menu with its first item focused.
- **AC15.** Escape closes the menu and focuses its trigger. Choosing an item closes the menu and focuses the trigger, so focus is never lost to body. Tab or Shift+Tab closes the menu.
- **AC16.** Escape with no menu open changes nothing.
- **AC17.** Every trigger, item, link and the toggle shows the `:focus-visible` ring. There is no `all: unset`.
- **AC18.** tanzi.os menu: About this site (`open site`), a divider, Restart… (`restart`, which keeps the settings).
- **AC19.** Windows menu: the five `WIN_TITLES` items, each checked when its window is open and not minimized. Choosing one dispatches `open`. Then a divider, Minimize all, Show all and Tidy up.
- **AC20.** View menu: Dark mode and Light mode (radio), a divider, the three Wallpaper items (radio), a divider, Wobbly windows (checkbox).
- **AC21.** Help menu: Terminal commands (`open term`), Résumé (PDF) (`RESUME_URL`, new tab, noopener), a divider, Say hi with the hint "email" (`mailto:` + `EMAIL`).
- **AC22.** Choosing an already-checked radio item changes no state and still closes the menu.
- **AC23.** The first React theme equals `<html data-theme>`. There is no flash and no second fallback rule. Stored light gives light, stored dark gives dark, missing or invalid follows the OS, and a throwing storage gives dark.
- **AC24.** Changing the theme from the menu, the toggle or an effect updates `<html data-theme>` straight away, flips the toggle icon and label, and writes `tanzi-os:theme`.
- **AC25.** The background is `var(--wall-<wall>)`, default nebula. Changing it writes `tanzi-os:wallpaper`. A missing, invalid or throwing value gives nebula.
- **AC26.** Wobble defaults to on and is stored as `'true'`/`'false'` (anything else gives on). It is passed to `WindowLayer`, and the hard-coded `wobble={true}` is removed.
- **AC27.** Every storage access is in try/catch and uses the `tanzi-os:` prefix. When storage fails, the app still renders and the setting still changes for the session. No other keys are written and no layout is persisted.
- **AC28.** One path covers theme, wallpaper, open, tidy and restart. A unit test shows that the matching effect and menu action give the same state and the same writes. `clear` is excluded.
- **AC29.** Restart and Tidy keep theme, wallpaper and wobble, and leave the stored values as they are.
- **AC30.** Clock format is `<Wkd> <h>:<mm> <AM|PM>` with ASCII spaces and no dependence on locale (the four examples in the requirements).
- **AC31.** The clock formatter is pure, takes numbers, and is unit-tested for midnight, noon, 11:59 PM and all seven weekdays.
- **AC32.** The clock shows on the first render. It ticks at most every 15s, the interval is cleared on unmount and StrictMode does not leak it. It uses tabular numerals, neutral-300 and `0 6px 0 10px` padding, is not focusable, and is a `<time dateTime>`.
- **AC33.** On hover, links get `translateY(-2px) rotate(-8deg)` on the bouncy ease and the toggle gets `rotate(40deg)`. Reduced motion removes these transforms. Menus are not animated.
- **AC34.** Under reduced motion, Wobbly still toggles and persists but never tilts.
- **AC35.** AA contrast in both themes, checked with `tests/helpers/contrast.ts`. Menu text is checked on surface, accent 16% and accent 26%, and the hint on surface. Trigger labels, the tanzi.os label and the clock are checked on the menubar background composited over bg, section and accent-900. Link and toggle icons need 3:1.
- **AC36.** Minimized windows stay unreachable while menus are open and after menu actions. Minimize all leaves no window control in the tab order.
- **AC37.** The pure logic lives in `src/logic` and is tested (index wrap and skip, clock, value parsing, settings and menu transitions). Storage and `documentElement` helpers live in one module outside `src/logic`, tested for valid, invalid, missing and throwing storage.
- **AC38.** Component tests cover AC6-AC8, AC10-AC16 and AC18-AC22, including checked states that update after an action.
- **AC39.** E2e at 1280x720 covers: click and keyboard opening, Escape focus return, click-outside, theme and wallpaper surviving a reload, wobble off giving no tilt, Tidy and Restart keeping the settings, and the clock regex.
- **AC40.** Broken existing tests are rescoped without being weakened and are listed as deliberate requirement changes (section 7a). No test is deleted or skipped.
- **AC41.** lint, typecheck, test, build, format:check and test:e2e are all green, with no console errors or warnings in e2e.

**Added ACs (gaps found):**

- **AC42 (added).** When the menu closes because of a pointer-down outside it, focus is not moved. In particular, focus is not pulled back to the trigger, so the window the user pressed keeps its normal focus and raise behaviour.
- **AC43 (added).** The menubar's `document` listeners (outside pointer-down, Escape) exist only while a menu is open. They are removed on close and on unmount. Under StrictMode there is no net listener after unmount and no console error or warning.
- **AC44 (added).** Nothing is written to storage on load, or when the chosen value equals the current one (AC22, Assumption 6). This means a visitor who never changes the theme keeps following `prefers-color-scheme`.

## 3. Architecture

**Approach.** The settings sit next to the window `State` in a single top-level reducer. `Desktop`'s `useReducer` switches from `desktopReducer` to `appReducer(App, AppAction)`, where `App = { desk: State; settings: Settings }`. `appReducer` sends window actions to the existing `desktopReducer`, which is untouched, so Restart and Tidy cannot reach the settings (AC29). It sends settings actions to `settingsReducer`. The single path for AC28 is `dispatch(AppAction)`. Menu items dispatch `AppAction`s directly. Terminal effects go through `effectToAction(effect)`, a pure function that returns `AppAction | null` (`clear` gives null). Side effects run in one place in `Desktop`: a `useLayoutEffect` keyed on `settings` calls `applyTheme` and writes the pure `persistDiff(prevRef.current, settings)`. Because `prev === next` on mount, nothing is written at load (AC44), StrictMode re-runs write nothing, and every path (menu, toggle, effect) persists the same way. Menu open/focus state is UI-local in `MenuBar` (`useState`), following the CLAUDE.md convention.

**MenuBar markup and behaviour.**

```
<header className="mb" aria-label={MENUBAR_LABELS.landmark}>
  <div role="menubar" aria-label={MENUBAR_LABELS.menubar} className="mb-menus">
    {MENU_ORDER.map(id => <div role="none" className="mb-slot">       // slot is full height, position: relative
      <button type="button" role="menuitem" id={`mb-trigger-${id}`} aria-haspopup="menu" aria-expanded={open===id}
              tabIndex={roving===id ? 0 : -1} className="mb-trigger" data-open={open===id}>…label…</button>
      {open===id && <div role="menu" aria-labelledby={`mb-trigger-${id}`} className="mb-menu">  // absolute, top 34px, left 0
         entries → <button type="button" role=… aria-checked=… tabIndex={-1} className="mb-item">
                     <span className="mb-check"><Check aria-hidden/> or empty</span><span>{label}</span>{hint && <span className="mb-hint">}</button>
                 | link items → <a role="menuitem" tabIndex={-1} href … {...newTab attrs}> (same inner layout)
                 | <div role="separator" className="mb-sep"/>
      </div>}
    </div>)}
  </div>
  <div className="mb-right">
    {LINKS.map(l => <a className="mb-link" href={l.href} aria-label={l.label} {...linkAttrs(l.href)}><l.icon size={16} aria-hidden/></a>)}
    <button type="button" className="mb-toggle" aria-label={dark ? toLight : toDark} title={toggleTitle}
            onClick={() => dispatch({type:'toggleTheme'})}>{dark ? <Moon/> : <Sun/>}</button>
    <Clock/>
  </div>
</header>
```

- The tanzi.os trigger has the extra class `mb-trigger-os` and contains `<CircleHalf aria-hidden />` plus the label `MENU_TITLES.os`. Its accessible name is exactly "tanzi.os".
- Résumé is a `link` cmd with `href: RESUME_URL` and `newTab: true`, rendered with `target="_blank" rel="noopener noreferrer"`. Say hi is a `link` cmd whose href `menuModel` builds as `'mailto:' + EMAIL` (imported from `../data`), with `newTab: false` and no target.
- State: `open: MenuId` and `roving: TopMenu` (default `'os'`), plus refs to the triggers and the items of the open menu. A `pendingFocus: 'first' | 'last' | null` ref is applied in a `useLayoutEffect` after the menu renders.
- Pointer: the trigger's `onClick` runs `menuTransition(click)`. `onPointerEnter` runs `menuTransition(hover)` and sets `roving`. Item `onClick` runs the cmd (`dispatch(action)`, or native navigation for `<a>`), then `close({ refocus: true })`.
- Keyboard on a trigger (`onKeyDown`, with `preventDefault` for the handled keys):
  - ArrowLeft/Right: roving and focus move with `nextTrigger`. If a menu is open, it switches.
  - Home/End: first or last trigger.
  - Enter, Space, ArrowDown: open with focus on the first item.
  - ArrowUp: open with focus on the last item.
  - Escape: close.
- Keyboard on an item:
  - ArrowUp/Down: `stepItem`.
  - Home/End: `firstItem` or `lastItem`.
  - Enter or Space: `el.click()` (Space needs this for `<a>`).
  - ArrowLeft/Right: open `nextTrigger` and focus its first item.
  - Escape: close and refocus the trigger.
  - Tab: close with no refocus and no `preventDefault`.
- `close({ refocus })` sets `open = null`. If `refocus`, it focuses the trigger of the menu that was open.
- While `open !== null`, one effect adds two `document` listeners and removes them in its cleanup (AC43):
  - `pointerdown` in the capture phase: if the target is outside the header, close without refocus (AC42). It never calls `preventDefault`/`stopPropagation`, so the window still raises (AC8).
  - `keydown`: Escape closes and refocuses the trigger. This covers menus opened by pointer while focus is elsewhere.

  With no menu open there are no listeners, so AC16 holds trivially.

- `onBlur` of the header (focusout with `relatedTarget` outside the header, and not null) closes the menu without refocus. This handles Shift+Tab out.

## 4. Design

- **User flow.**
  - Load: the menubar sits on top of the wallpaper (stored or nebula). The clock shows straight away, and the theme matches the inline script.
  - Click "Windows": the dropdown shows the five windows with checks. Click "terminal" after minimizing it: it restores and comes to the front, the menu closes and focus returns to the trigger.
  - View: switch the theme or wallpaper (instant, and it persists), or turn wobble off (dragging no longer tilts).
  - Tidy up or Restart: the layout resets and the settings stay.
  - Keyboard: Tab focuses "tanzi.os", the arrows move across the triggers, ArrowDown opens a menu, and Escape returns focus to the trigger.
- **States.**
  - Loading: none (synchronous).
  - Empty: all windows closed or minimized. The Windows menu shows no checks, and Show all, the window items or Tidy up bring them back. This is the first real recovery path.
  - Error: storage throws, so the defaults are used and changes stay session-only. `/resume.pdf` is missing, so a 404 page opens in a new tab (acceptable, T10). No mail client means the OS handles mailto.
  - Success: as in the flow.
  - Open menu: exactly one at a time, and the trigger shows the 10% background.
- **1280x720 and larger.** The 36px bar spans the width. The longest dropdown (Windows, about 9 entries at about 32px each) fits easily within 720px. The Help dropdown, last trigger, starts about 240px from the left, so it never overflows the right edge. Windows keep y >= 36 (existing clamp), so nothing sits under the bar. Mobile is not built.
- **Accessibility.**
  - It uses the WAI-ARIA menubar pattern (AC10-AC15). Triggers are `role="menuitem"` buttons, so they are not counted as buttons.
  - The tab stops before the windows, in order, are the tanzi.os trigger (roving), GitHub, LinkedIn, Email and the theme toggle. That is five tab stops.
  - The clock is not focusable but can be read as `<time>`.
  - The focus ring comes from the global `:focus-visible`. Item hover and focus share the 16% background.
  - Contrast is verified by AC35 tests. If a pair fails, use the nearest existing token that passes in both themes (for example `--color-text` for trigger labels), log it in the QA report, and add no new tokens unattended.
- **Reduced motion.** Hover transforms on links and the toggle are removed, and the colour changes stay. Menus have no animation in any mode. Wobbly still toggles and persists, and `Window` already suppresses tilt (AC34).

## 8. Open questions

None needing a human. These choices were made unattended, each the simplest option:

1. **Settings live next to `State` in `App`,** not inside `State`. This keeps `desktopReducer` and its tests untouched, and makes AC29 structural.
2. **Focus after any item, including window-opening ones, returns to the trigger.** Assumption 3 allows this, it is uniform, and it is never lost.
3. **No write when a chosen value equals the current one** (AC44). This keeps OS-following for visitors who never actually change a setting.
4. **The theme toggle is a native `button`,** which is why the page-wide button count goes from 10 to 11 (7a).
5. **Persistence and `data-theme` are applied in a `useLayoutEffect` keyed on settings,** so menu, toggle and future terminal effects share one side-effect site.
